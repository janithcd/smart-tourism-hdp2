# Profile photos on the free Firebase plan

The app's photo picker accepts a JPEG, PNG, or WebP image up to 5 MiB. It copies the selected file into the app's private `getNoBackupFilesDir()` directory under a filename derived from the signed-in Firebase UID. This needs no broad photo permission and no Firebase Cloud Storage. The image appears in Profile and the drawer for that account on the same app installation. The copy is not uploaded, backed up, or transferred to another phone, and it is lost if the app is uninstalled or its data is cleared. Older HTTPS profile photo URLs saved in Firestore still display when that account has not chosen a local photo. A legacy Firebase Storage path is not downloaded on the free plan.

Firebase currently requires the pay-as-you-go Blaze plan for Cloud Storage; on Spark, Storage API requests can return 402 or 403. The local design deliberately avoids that service. No Storage bucket or Storage rules need to be created or deployed for this feature. The Help page's phone and email contacts are the [Sri Lanka Tourism Development Authority's published contacts](https://sltda.gov.lk/en/developing-planning), labelled as external tourism contacts rather than app booking support.

For a viva, explain: “The Firebase project uses the free Spark plan, so profile photos are stored privately on this device and scoped to the signed-in user. They work offline and do not sync across devices. A future cloud photo feature would need an approved storage service and appropriate access rules.” Do not describe demo booking submissions as actual reservations.

Test with [checklist steps 20–21](manual-test-checklist.md) on a physical device. Android build and Firestore rules tests run in CI; neither can prove picker behavior or internal file persistence on a device.
