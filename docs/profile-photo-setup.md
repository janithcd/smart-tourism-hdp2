# Profile photo and Help setup

The app uses the Android photo picker to select a JPEG, PNG, or WebP image up to 5 MiB. It uploads one avatar per signed-in user to `profile_photos/{uid}/avatar` in the default Firebase Storage bucket and stores that path in the owner's Firestore `users/{uid}.profilePic` field. The avatar is read through the authenticated Storage SDK; no public download URL is saved. Older HTTPS avatar URLs still display, and new accounts use the bundled default icon until a photo is selected. The Help page links to the [SLTDA public contact page](https://sltda.gov.lk/en/developing-planning), whose tourism hotline, office phone and email are explicitly marked as external contacts. They do not process this app's demo bookings.

## Enable photo uploads in `smart-tourism-abbb0`

1. In Firebase Console, open **smart-tourism-abbb0** → **Build** → **Storage**. Firebase currently requires a **Blaze** billing plan to use Cloud Storage. Decide on billing and a bucket location in the console before creating the default bucket; neither the app nor this repository changes the plan automatically. The included `app/google-services.json` lists `smart-tourism-abbb0.firebasestorage.app`; check that the bucket name in Storage matches it.
2. Open **Storage → Rules**. Review the current deployed rules, especially any paths used by your separate admin app. Add the scoped `profile_photos/{uid}/avatar` rule from [`storage.rules`](../storage.rules) while preserving other required paths with similarly narrow access. Replacing existing rules wholesale can break the other app. Publish the combined rules to this bucket. These rules allow an owner to read, upload, replace and delete only their avatar, reject listing, and limit MIME types and size. Firestore's separate `users/{uid}` rules must also be published for updating `profilePic`.
3. Run `npm install` and `npm run test:rules:emulator` with Node.js 22 and Java 21 to check both Firestore and Storage rules against local emulators. Then use the [device checklist](manual-test-checklist.md), steps 20–21, with the real Firebase project. An emulator pass cannot prove the live bucket/rules are configured.

If an upload fails, check that you are signed in, the Storage bucket and rules are active, the Firebase project and bucket name match, and the file is a supported image within the size limit. The app does not require broad photo library or phone-call permissions. Gmail is preferred for email compose; an installed email app is used if Gmail is absent.
